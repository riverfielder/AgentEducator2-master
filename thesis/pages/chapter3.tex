本系统主要服务于两类核心用户角色，其业务范围与权限边界如下：
\begin{itemize}
    \item \textbf{学生（学习者）}：系统的主要服务对象。具有浏览课程、申请个性化学习路径推荐、参与视频知识问答（RAG联动）、提交代码实训任务及查看个人学习图谱的权限。无权修改课程本体及查看其他学生数据。
    \item \textbf{教师（管理者）}：系统的资源维护与教学监督者。具有完整的课程资源管理权限（包括但不限于课件、教案、习题、作业、实践项目、视频、教材等所有课程相关教学资源的上传与编辑），同时具备学情监控权限，可查看选课学生的学习进度、高频错题及整体代码实训成功率。
\end{itemize}

\section{业务需求概述}
在线个性化学习系统旨在改变传统 MOOC 平台固定统一化的教学模式，为学习者提供智能导学、交互式知识问答、启发式代码实训以及基于历史行为的个性化课程推荐。教师则通过平台上传并管理完整的课程资源、布置实训任务并监控总体及个体的学习进度。

\subsection{用例规约}

在给出了全业务流程的用例图后，以下采用《写作指南》中标准的用例规约模板逐个详细展示核心用例的完整要素。

\vspace{1em}
\noindent\textbf{【用例1：用户登录认证】}\\
\textbf{参与者}：学生、教师\\
\textbf{目标}：验证用户身份，分发合法的 JWT 会话凭证，保障系统数据安全。\\
\textbf{前置条件}：用户已在系统注册过有效账号。\\
\textbf{触发条件}：用户在登录页面输入账号密码并点击登录。\\
\textbf{主场景}：
\begin{enumerate}
    \item 用户输入用户名和密码。
    \item 前端对密码进行初步校验后发送加密登录请求。
    \item 后端校验哈希密码，验证成功后签发包含用户角色（Role）的 JWT 返回给前端。
    \item 前端存储凭证并路由至对应角色的首页。
\end{enumerate}
\textbf{扩展}：若密码连续输入错误超过 5 次，系统触发安全风控，冻结账号登录渠道 15 分钟。\\
\textbf{泛化}：无。\\
\textbf{发生频率}：高，峰值约 500 次/分钟（如集中上课时段）。\\
\textbf{限制}：密码传输必须通过 TLS 加密，单次 JWT 签发有效期限制为 2 小时。\\
\textbf{注释}：后续所有业务接口均依赖此鉴权结果。

\vspace{1em}
\noindent\textbf{【用例2：课程资源管理】}\\
\textbf{参与者}：教师\\
\textbf{目标}：教师在平台上统一管理课程相关的所有教学资源（课件、教案、习题、实训、视频、教材等），并建立后台知识库索引。\\
\textbf{前置条件}：教师已登录系统并进入后台管理面板。\\
\textbf{触发条件}：教师点击“新建课程”或“上传资源”按钮。\\
\textbf{主场景}：
\begin{enumerate}
    \item 教师填写课程元数据并选择各类型资源文件上传。
    \item 系统将多媒体或文档资源保存至持久化存储。
    \item 后端触发异步任务，对视频进行截取、语音识别；对文档进行解析。
    \item 框架将文本向量化并写入 FAISS 数据库。
    \item 前端展示资源处理成功的状态圆点。
\end{enumerate}
\textbf{扩展}：若资源类型受损或无法解析，系统跳过向量化步骤仅做文件存储，并高亮标记异常类型给教师。\\
\textbf{泛化}：资源上传泛化为“视频资源处理”与“纯文本资源处理”两种独立管线策略。\\
\textbf{发生频率}：低，约 50 次/周。\\
\textbf{限制}：单次上传视频文件最大限制为 2GB，文档类资源最大为 50MB。向量化并发任务最高限制为 3 个工作线程。\\
\textbf{注释}：该环节产生的 FAISS 索引是后续 RAG 视频问答的直接前置依赖。

\vspace{1em}
\noindent\textbf{【用例3：个性化学习路径推荐】}\\
\textbf{参与者}：学生\\
\textbf{目标}：系统根据学生的历史行为、错题记录及能力画像，为其推荐动态、专属的后续学习知识点与课程视频。\\
\textbf{前置条件}：学生至少产生了 1 条视频播放或代码实训的埋点记录。\\
\textbf{触发条件}：学生进入“学习主页”或完成某章测验后。\\
\textbf{主场景}：
\begin{enumerate}
    \item 系统拉取学生的历史完课率、能力雷达图及 AST 实训留存的易错高频节点。
    \item 调用协同过滤算法与启发式画像分析引擎。
    \item 引擎匹配并计算出学生当前的技能断层薄弱点，生成下一个阶段的推荐课程节点。
    \item 前端渲染高保真的推荐知识图谱，高亮并闪烁建议优先学习的资源卡片。
\end{enumerate}
\textbf{扩展}：若新注册学生（无历史数据），触发冷启动兜底策略，按通用的平台首推章节流分发。\\
\textbf{泛化}：无。\\
\textbf{发生频率}：中，每次用户进入平台首页时触发查询。\\
\textbf{限制}：接口防抖，同设备 10 分钟内的重复请求统一命中 Redis 一级缓存。\\
\textbf{注释}：重点衡量系统千人千面“个性化”差异指标。

\vspace{1em}
\noindent\textbf{【用例4：启发式代码提交与评测】}\\
\textbf{参与者}：学生、评测子系统、大语言模型服务\\
\textbf{目标}：学生在不直接获得答案的情况下，通过多次提交代码获取针对深层逻辑缺陷的引导反问，培养独立思考与重构能力。\\
\textbf{包含}：登录认证用例。\\
\textbf{前置条件}：学生进入了具体的智能代码实训题目页面。\\
\textbf{触发条件}：学生编写代码完毕，触发“编译并提交 AI 评审”命令。\\
\textbf{主场景}：
\begin{enumerate}
    \item 前端封包当前语言类型、代码原文及历史提交试错次数。
    \item 后端评测子系统调用 Python 的 \texttt{ast} 模块，对接收代码展开静态结构树与分支复杂度解析。
    \item 结合代码黑盒报错栈与静态分析异常缺陷报告，组合至预设的“苏格拉底系统提示词模板”。
    \item 请求云端或本地大模型，输出“不直接包含正确代码”的逆向探讨与修改线索建议。
    \item 前端打字机渲染 AI 反问提示，更新试图尝试徽章。
\end{enumerate}
\textbf{扩展}：当某题目错误累积尝试次数达到 5 次上限边界时，大语言模型的 Prompt 转变为“直接详解模式”，下发带完整正确参考代码的解析供比对学习。\\
\textbf{泛化}：无。\\
\textbf{发生频率}：极高，单次课堂实训课可达数百并发/分钟。\\
\textbf{限制}：评测沙箱核心严格开启读写物理隔离拦截（禁用 \texttt{os.system}、\texttt{sys} 等库映射），此沙箱单容器进程运行期内存占用被硬隔离卡死在 \le 128MB。\\
\textbf{注释}：核心实战环节。

\vspace{1em}
\noindent\textbf{【用例5：视频播放与AI智能问答】}\\
\textbf{参与者}：学生、检索服务、大语言模型服务\\
\textbf{目标}：学生对课程视频疑惑时提问，AI 结合该视频特定的私有知识库做出抗“幻觉”的解释，并提供带时间戳的实证引用。\\
\textbf{前置条件}：相关资源的 FAISS 向量库构建完毕且学生进入视频页。\\
\textbf{触发条件}：学生在聊天区域回车或点击“发送”侧边栏提问。\\
\textbf{主场景}：
\begin{enumerate}
    \item 学生以自然语言输入上下文相关的学习问题。
    \item 后端利用 RRF 倒数秩融合算法混合词频与语义余弦相似度检索，精准召回该问题对应的视频字幕段与讲义切片。
    \item 拼接带有时间码的上下文交付给大模型流式推理引擎。
    \item 前端应用流控接收，在回答的 Markdown 文档中绘制出如 \texttt{[1]} 等角标源标。
    \item 学生点击角标，视频播放器通过内部调度精确 Seek（跳跃）并播放引用对应的课堂时间节点。
\end{enumerate}
\textbf{扩展}：若大模型判定该问题无法从给定该视频切片中寻获事实依据（离题），必须回答模型幻觉免责声明“基于当前知识范围内未找到答案...”。\\
\textbf{泛化}：无。\\
\textbf{发生频率}：中。\\
\textbf{限制}：生成流的 TTFT 必须低于 2 秒以保证强实时性。\\
\textbf{注释}：本用例体现了相较于传统视频问答的精准度层级的代际提升。

\vspace{1em}
\noindent\textbf{【用例6：教师学情监控】}\\
\textbf{参与者}：教师\\
\textbf{目标}：教师宏观掌握选课学生的群体学习进度与高频逻辑错误雷达图结构，适时干预教学方针。\\
\textbf{前置条件}：教师账号进入所建课程的管理或“学情仪表盘”页。\\
\textbf{触发条件}：教师点击“统计分析”或进入控制台首页。\\
\textbf{主场景}：
\begin{enumerate}
    \item 后端数据中台拉取本班多位学生的视频均完课时长、互动发生频次。
    \item 将学生端传回的报错 AST 节点类型与成功率归一化统算占比。
    \item 按最高权重汇总逻辑漏洞黑区（诸如循环无边界、变量内存越界等）。
    \item 将以上维度抛回浏览器由 ECharts 渲染成数据看板折线/雷达图解。
\end{enumerate}
\textbf{扩展}：检测到单个学生进度（如完课比< 20\%）处于下限阈值，对其展示出警视灯图标以便教师手动发送敦促提醒信。\\
\textbf{泛化}：无。\\
\textbf{发生频率}：低。\\
\textbf{限制}：多维度表连接分析查询时长限制不超过 3.0 秒。\\
\textbf{注释}：教育工作链路管理闭环模块。


\section{非功能性需求分析}

非功能性需求在此定义了系统运行环境下的质量特性。结合系统实际复杂业务，本处严格制定了其可量化的验证标准、测试工具及测试合格场景：

（1）\textbf{性能需求}：
\begin{itemize}
    \item \textbf{网页加载响应}：要求核心主单页面资源（例如主页知识图谱与视频库区）不应造成视觉渲染长锁块。
    \textbf{详细验证细则}：利用浏览器 Google Lighthouse 工具测试网络在典型 Fast 3G 或更优环境下，测算 FCP（First Contentful Paint）指标 \le 2.5s 即为测试通过合格阈值。
    \item \textbf{流式问答响应（TTFT）}：系统对于涉及大语言模型的业务，首答延迟需维持体验底线。
    \textbf{详细验证细则}：采用 Postman 脚本化打版并发请求，发起稳定 30 并发测试链路计算流生成的首个可识别回答 Token 耗时，要求 95\% 节点的耗时界限 \le 2000毫秒 且期间无一次 HTTP \texttt{504 Gateway Timeout} 即视同判定合格。
    \item \textbf{并发处理能力（吞吐指标）}：对于核心的代码评测试错交互管线高峰处理负载支撑。
    \textbf{详细验证细则}：依托于 Apache JMeter 开源性能套件施加 100 活跃线程并发进行 5 轮次无停顿循环测试压制。合格判定标准需要满足业务均向吞吐量 $TPS = \frac{N}{T} \ge 50$ 笔/秒，且核心错误失联率 \le 1\%。此外，代码执行沙箱任务被物理设定为 5 秒满上限斩断回收。
\end{itemize}

（2）\textbf{可靠性需求}：
\begin{itemize}
    \item \textbf{容错与脱解验证}：长耗时异步任务必须防范失败致整系统宕机。
    \textbf{详细验证细则}：人为向教师上传侧植入残损异常大底视频数据引发处理机后端进程报错，主 HTTP 接口服务必须能够隔离处理该错报不引起雪崩，响应体应持续回复 HTTP \texttt{200}；且记录进入运维级“死信队列”标注并容许人工二次补重即为可靠性检证标准合格。
\end{itemize}

（3）\textbf{安全需求}：
\begin{itemize}
    \item \textbf{认证鉴权校验防伪}：系统杜绝非法越权资源串调。
    \textbf{详细验证细则}：截包剥离请求头里的 \texttt{Authorization} 签名内容向系统高权限核心数据域发出索取包。预期后端服务应具备完密路由守卫，强行卡断发落判定标准 \texttt{401 Unauthorized} 或 \texttt{403}。
    \item \textbf{代码执行安全约束}：禁止学生端直接访问或侵入测试主服务器内核数据。
    \textbf{详细验证细则}：用学生号实机提交恶意代码段诸如 \texttt{import os; os.system('cat /etc/passwd')}，此恶意串进入系统必须被在编译器执行前由预设的内置黑名单树通过 AST 筛拦截，系统拒接返回且不执行底层任何内存篡改则为测试判定合格。
\end{itemize}

\section{约束}
由于软硬件等环境因素，本在线学习环境平台被严格施加以下几类明确的量化约束：

\begin{itemize}
    \item \textbf{物理维度限制（算力天花板）}：部署云端主环境限配 4核心+8G内存主机。
    因此强量化约束在于：1）平台同时开放挂载的大型后台并发计算分析长进程封顶控制不得超过 8 个；2）单个处理教师端音视频长文件的转编与词矢量化耗能极高，单异步内存峰值警戒上限拉低至 1.5GB 防护；3）并发量中全主运行宿主内所有环境综合内存上限水位 $M$ 被规定不允突破 $8GB \times 80\% = 6.4GB$ 以防大面积 OOM（Out Of Memory）。
    \textbf{项目与架构业务约束}：因毕业进度周期设定，系统将大模型基座托管给云端可规模集调商用级 API，由它专注解决算力输出；系统在本地实现核心混合架构工程组装（全前后端分离、Python 专属负责整合 AST 分析核心及轻量库管理路由）。
\end{itemize}
