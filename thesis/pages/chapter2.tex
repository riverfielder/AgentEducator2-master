\chapter{国内外现状}

\section{竞品分析}

MOOC 及各类在线学习平台的兴起在推动教育创新方面起到了重要作用。国外的 Coursera、edX 等平台凭借其丰富的课程资源吸引了全球学习者，国内亦有“中国大学MOOC”等主流平台提供了大量本土化的优质课程。然而，深入剖析同类教育与评测产品（如智学网、LeetCode、牛客网等 OJ 系统），可以发现它们在个性化学习辅助方面存在显著的功能痛点，难以凸显新一代智能教育平台的优势：

首先，在代码实训反馈方面。传统的在线评判系统（OJ）如 LeetCode 和牛客网主要依赖于黑盒测试用例的比对，对学习者提交代码进行批阅。当测试未通过时，系统只能提供“答案错误”或抛出底层运行级别的异常信息，较少能够分析代码中的具体逻辑缺陷。这种缺乏针对性辅导的反馈，导致学习者在遇到瓶颈时往往直接查阅标准答案，形成了极大的依赖性。相比之下，本系统基于大模型（LLM）与抽象语法树（AST）设计的苏格拉底代码启发实训，能够通过识别由于语法结构或控制流错误引发的深层漏洞，为学习者反馈渐进性、引导性质的思考线索，促使其自行修改代码，充分凸显了个性化辅导的创新价值与差异化优势。

其次，在视频知识解答交互层面。尽管部分平台引入了弹幕或讨论区，但在海量视频语料的答疑中，往往依赖人工回复或检索历史问答，效率低下且缺乏上下文的关联理解。部分尝试接入通用大模型的平台也面临着教育垂直领域“幻觉”严重、解答不可溯源等缺陷。本系统引入的视频联动 AI 问答，能在视频播放至特定时间节点时，进行高度精准的帧级别与语境级别的问题解析，补齐了同类产品视频问答精准度低的问题。

\section{关键技术分析}

在线教育系统向智能化的演进离不开先进算法与技术的支撑。现有的多数评测系统在技术方案上，仍未深入结合微观层次的上下文语义理解逻辑。

\subsection{混合检索与 RAG 技术}
在特定领域或私有知识库应用中，纯通用大模型容易产生“幻觉”，而多数平台仍使用传统的倒排索引检索（如单纯基于词频的 BM25 技术\cite{whu-bachelor:14}），其面对多模态数据和复杂的自然语言时，语义理解能力较差。本系统引入检索增强生成（RAG），并且在向量相似度以外设计了混合检索策略：通过将 BM25 词汇匹配召回的结果与特征向量余弦相似度召回的结果，经过倒数秩融合（RRF, Reciprocal Rank Fusion）重排算法进行综合排序打分。RRF 重排算法能够平滑两种检索方式的得分尺度差异，既保障了专业教育名词匹配的精确度，又利用了语义关联检索的泛化能力。系统将知识库（如课程字幕、讲义文档）转化为稠密向量存入 FAISS 数据库中，结合 LLM 生成准确且带有视频时间戳溯源的回答，实现了比同类教育应用更可控且具备高解释性的技术路线。

\subsection{抽象语法树（AST）与启发式教学机制}
目前的在线学习平台对代码的白盒分析较为粗糙。本系统不仅结合了黑盒运行沙箱，更深入实现了静态代码分析技术。不同于常规的文本匹配纠错，系统通过 Python 内置的 \texttt{ast} 模块，对学习者提交的代码进行节点遍历与解析，将源代码映射为树形层级结构（Abstract Syntax Tree）。通过制定针对特定题目的 AST 节点遍历规则（例如检查 \texttt{For} 节点、\texttt{If} 分支节点的嵌套情况），可以精准提取圈复杂度、变量命名规范等底层指标。同时，此分析不仅停留于寻找静态代码异常，它还作为“苏格拉底式”启发式教学引擎的核心输入：当 AST 分析引擎检测到代码特定的错误模式后，并不直接提供正确片段，而是将其与题目描述一同包装至大模型的输入模板中，由大模型逆向生成具有引导性的测试用例和思路探究问题。这种对 AST 技术在教育实境中的特化适配，有效奠定了后续实现个性化反馈的理论基础保障。

\section{开发工具与平台分析}

在综合考察现有的技术生态与平台架构选型后，本系统以易扩展性、高性能以及与 AI 算法栈的完美适配为导向，确立了系统的横向技术组合。相比开发同类平台常见的陈旧架构体系，本系统的选型展示出了显著的架构与业务优越性：

\subsection{前端开发框架选型对比}
目前业界流行的前端框架包括 React 与 Vue 系列。React 拥有极其庞大成熟的生态，但其相对较高的学习曲线与严格的函数式不可变性要求，在快速构建中小型响应式业务系统中稍显繁重。本系统前端选择 Vue 3 框架并结合 Vite 构建工具。Vue 3 的 Composition API 使得相关关注点的逻辑代码得以高度聚集，并在状态管理（配合 Pinia）时提供了极简流畅的数据流向。系统借助 Element Plus 和 Vuetify 构建了现代化的用户界面，通过响应式的 HTML5 视频播放器和打字机流式长连接事件机制，保证了教育互动场景下的极低延迟反馈，其开发效率与渲染性能完全适应本业务需求。

\subsection{后端应用架构选型对比}
传统的教育管理系统后端多倾向选用 Java 体系（如 Spring Boot）。基于 Java 的服务在大型企业级并发治理上拥有优势。但对于以人工智能辅导为核心的新型教育应用而言，绝大多数机器学习模块、AST 语法分析模块均是以原生 Python 向外暴露接口。由于需要在同一服务域内调用大语言模型框架，若采用 Java 搭配 Python 微服务的双重架构将极大增加了系统的维护与通信成本。因此，本系统后端选用 Python 的微框架 Flask。相比重量级的 Django 框架，Flask 轻量透明、可扩展性强。结合 SQLAlchemy ORM 及线程池异步任务控制，不仅实现了良好的关系型数据库持久化处理，而且极其自然地集成了大语言模型与各类向量化耗时任务队列。

\subsection{向量数据库选型分析}
主流向量数据库包括 Milvus 和 FAISS。Milvus 是一款完整的分布式向量数据库，支撑百亿级别检索，在一台轻量服务机上实施重量较重。本系统基于业务边界隔离策略最终选定 FAISS。它不仅能够在内存和磁盘之间提供快速余弦相似度检索，而且通过封装无侵入地融入 Flask 应用进程，极其恰当地满足了本系统的即时索引需求。
