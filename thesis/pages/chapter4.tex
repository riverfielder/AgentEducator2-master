\chapter{系统设计}

\section{总体设计}

本系统摒弃了传统的单体应用或简单的微服务架构，针对在线教育中 AI 核心能力的深度融合需求，重新设计并特化了带有 LLM 调度中间件、AST 静态分析引擎及 RAG 混合检索引擎的分层架构。总体架构自下而上分为基础设施层、数据持久层、业务核心服务层（含 AI 特化层）及表现层。该架构不仅解决了传统平台“一刀切”的瓶颈，而且显著提升了代码诊断与知识检索的精准度。

  \centering
  \includegraphics[width=\textwidth,height=0.4\textheight,keepaspectratio]{arch.png} % 架构图
  \caption{结合大语言模型分析与检索增强的特化系统架构图}
  \label{fig:architecture}
\end{figure}

架构各层级职责与特化交互规则解读：

（1）\textbf{基础设施层}：通过 Docker 容器化技术部署在云端 Linux 服务器上，使用 Nginx 进行动静分离与反向代理。这层保障了底层的网络隔离与负载均衡。

（2）\textbf{数据持久层}：采用多源存储架构以满足多模态学习数据的读写：
\begin{itemize}
    \item \textbf{MySQL}：存储强一致性的结构化业务数据（用户、课程、订单、实训记录）。
    \item \textbf{Redis}：作为高速缓存与消息中间件，维护短时问答会话上下文（Session）与系统状态机制。
    \item \textbf{FAISS 向量库}：AI 业务特化的多维稠密向量存储，负责持久化课程视频转录的字幕片段及教案提取的向量张量。
\end{itemize}

（3）\textbf{业务服务层（AI 核心组装层）}：这是本架构区别于传统教育管理系统（如基于 Java Spring 通用模型）的先进性所在。在 Flask 微框架底座之上，除了传统的认证鉴权、RESTful 数据分发等基础模块，核心构建了三大 AI 调度引擎：
\begin{itemize}
    \item \textbf{AST 代码分析引擎}：负责剥离自沙箱的白盒探测，提供圈复杂度、错误模式抽象树反馈。
    \item \textbf{RAG 混合检索引擎}：承接从 FAISS 中以余弦相似度及 BM25 词检索召回知识片段的聚合，执行倒数秩融合（RRF）重排。
    \item \textbf{LLM 调度中间件}：利用 LangChain 及定制的 Prompt 缓冲池，结合前两者的特征输入，流控式（SSE）调度云端大模型接口。各引擎之间通过异步线程池和事件驱动队列进行数据总线交互，大幅降低了主进程的阻塞。
\end{itemize}

（4）\textbf{表现层}：基于 Vue 3 组合式 API 构建的富客户端环境。特化了流式 Markdown 所见即所得渲染引擎、Markdown 引用角标与 HTML5 视频时间轴的事件委托联动模块，以及深度集成的代码动态 Web 编辑器沙盒视图。

\section{详细设计}

详细设计阶段对核心 AI 驱动模块与基础业务底座的结构形态进行细化规划，主要涵盖 UML 建模、数据库实体多重性及表结构全貌，以及符合工程化规范的 API 与界面设计。

\subsection{模块与 UML 设计}

为了深入剖析本系统两大创新能力（苏格拉底启发式代码评测，及视频知识 RAG 检索联动），本节选绘其核心的类图设计与交互时序图。

  \caption{启发式代码评测与视频 RAG 问答核心模块 UML 类图与时序图集成设计}
  \label{fig:sequence_code_eval}
\end{figure}

\textbf{类职责与动态设计解读：}
在代码评测与反馈体系中：前端发起的 \texttt{SubmitCodeCommand} 由后端的 \texttt{JudgeController} 接收。系统首先调用封装的 \texttt{ASTParser} 类对代码载荷构建抽象树并进行递归解析（如 \texttt{visit\_For}, \texttt{visit\_If} 等重写方法），产出包含指标数据的 \texttt{AnalysisReport}。若无明显错漏，代码才被送至 \texttt{SandboxExecutor} 实例中受限执行检查黑盒断言；任何阶段捕获的结构或逻辑异常均交由 \texttt{PromptBuilder}，结合“苏格拉底原则”拼装上下文后，通过 \texttt{LLMScheduler} 请求大模型。状态图层面，实训评测任务具备“等待”、“AST检验中”、“运行执行保护中”、“大模型推理中”、“结果渲染反馈”的单向状态流转链，此设计极大地剥离了评测业务的时序耦合度。

\subsection{数据库结构与实体 E-R 设计}

为了支撑系统架构的多模态承载、历史埋点追踪及角色权限区分，本系统必须厘清核心业务实体间的关联及多重性。

\begin{figure}[htbp]
  \centering

  \caption{基于多重性关联的系统核心 E-R 图}
  \label{fig:er_diagram}
\end{figure}

\textbf{实体间多重性与关联解读}：

（1）\textbf{User (1) $\leftrightarrow$ (*) Course}：一个教师角色（User）可以创建多门线上课程（Course），通过 \texttt{creator\_id} 外键实现 1 对多强关联。

（2）\textbf{Course (1) $\leftrightarrow$ (*) Video}：一门课程包含多个供学习的细分教学视频（Video）。

（3）\textbf{User (1) $\leftrightarrow$ (*) ChatSession (1) $\leftrightarrow$ (*) Message}：学生（User）有权发起并存留多段问答会话（ChatSession），每个会话下可包含多条按时序排列的问答消息记录（Message）。

（4）\textbf{User (1) $\leftrightarrow$ (*) CodeTaskRecord}：用户参与代码实训时，生成多条尝试与提交的溯源流水记录。

\subsection{接口设计（RESTful 规范）}

系统通信全部采用跨域适配的 RESTful API 范式。涵盖了请求动词、Header鉴权、载荷细则及统一的 JSON 异常脱敏格式机制：

\vspace{1em}
\noindent\textbf{1. 用户认证鉴权登录接口}\\
\textbf{描述}：接受用户明文输入，验证并派发应用 JWT 会话签标。\\
\textbf{URL}：\texttt{/api/auth/login} \quad \textbf{Method}：\texttt{POST} \\
\textbf{请求头 Headers}：\texttt{Content-Type: application/json} \\
\textbf{请求参数 (Body)}：
\begin{itemize}
    \item \texttt{username} (String, 必填)：用户的登录账号名。
    \item \texttt{password} (String, 必填)：用户的明文密码（受传输层安全协议保护）。
\end{itemize}
\textbf{响应结构 (HTTP 200)}：
\begin{verbatim}
{
  "code": 200,
  "message": "Login successful",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5c... (JWT String)",
    "role": "student",
    "user_id": 102
  }
}
\end{verbatim}
\textbf{异常响应 (HTTP 401)}：鉴权失败或撞库锁定状态则返回对应的错误业务码及拦截提示（如 \texttt{"code": 401, "message": "Invalid password"}）。

\vspace{1em}
\noindent\textbf{2. 启发式智能代码提交与评测接口}\\
\textbf{描述}：核心功能接口。接收学生代码，穿透 AST 与黑盒沙箱，触发 RAG 与 LLM 的启发评估链路并发还模型辅导文本。 \\
\textbf{URL}：\texttt{/api/code\_training/submit} \quad \textbf{Method}：\texttt{POST} \\
\textbf{请求头 Headers}：\texttt{Authorization: Bearer <有效JWT>} \\
\textbf{请求参数 (Body)}：
\begin{itemize}
    \item \texttt{task\_id} (Integer, 必填)：本轮实训的题目全局编号。
    \item \texttt{code\_content} (String, 必填)：前台编辑器传递来的实写 Python 源代码。
    \item \texttt{submit\_counts} (Integer, 选填/默认0)：该题目已触发的试错评测次数（驱动 AI 引导深度）。
\end{itemize}
\textbf{响应结构 (HTTP 200)}：
\begin{verbatim}
{
  "code": 200,
  "data": {
    "status": "KEEP_TRYING",
    "ast_report": {"cyclomatic_complexity": 8, "vulnerabilities": ["UnboundLocalError"]},
    "ai_reply": "你的核心思路非常接近了。但请注意在外层 for 循环处..."
  }
}
\end{verbatim}
\textbf{异常响应 (HTTP 403 / 500)}：若无 JWT 回掉 403。若大模型引擎超时熔断或沙箱死锁，统一下发 \texttt{"code": 500, "message": "Judgment cluster busy"}。

\vspace{1em}
\noindent\textbf{3. RAG 视频切片流式 AI 问答接口}\\
\textbf{描述}：依托 Server-Sent Events（SSE）长连接的推拉流问答服务，前端 EventSource 持续切块接收回答帧，构成首字极速渲染。 \\
\textbf{URL}：\texttt{/api/qa/ask-stream} \quad \textbf{Method}：\texttt{POST} （配合 \texttt{text/event-stream}）\\
\textbf{请求头 Headers}：\texttt{Authorization: Bearer <有效JWT>} \\
\textbf{请求参数 (Body)}：
\begin{itemize}
    \item \texttt{question} (String, 必填)：学生问询。
    \item \texttt{video\_id} (Integer, 必填)：划定知识检索 FAISS 扇区范围的视频标记。
\end{itemize}
\textbf{返回机制}：每次服务端下推一块形如 \texttt{data: \{"token": "它主", "source\_timestamp": null\}}\textbackslash{}n\textbackslash{}n 的裸事件载荷，其中特定的标识区块会挂载视频跳转偏移量（秒值）。

\subsection{系统高保真界面与核心交互设计}

本系统完全依据人机交互体验规范构建。为了具象化论证本文架构，本节结合前文设计的接口补充说明两大核心视图原型图景界面的架构功能匹配度与操作链路（截图及实际运行图见第六章系统测试展示）：

（1）\textbf{智能代码启发实训工作台模型}：
界面分为左右分栏（Split-Pane）主视场。左侧为题目 Markdown 富文本描述区与包含多步骤圆点的“学习路径进程卡”，以及呈现 AI“苏格拉底辅助提示”的仿终端高亮面板。右侧为集成了 Monaco Editor 或 CodeMirror 核心引擎的高性能代码编辑器，支持悬停高亮提示与语法补全。
\textbf{体验交互说明}：用户重构代码并点击 \texttt{Shift+Enter} 后，系统立即锁死工具栏阻挡并发穿透，左侧面板开启 Loading 骨架屏；约 2-3 秒等待后台 AST 闭环评审并驱动大模型后，左侧面板打字机式平滑展现引导语。若学生由于尝试耗尽解封标准答案，界面右下角浮出一个抽屉式的答案“Diff 对比窗口”，使得代码纠偏更为立体。

（2）\textbf{视频联动 AI 知识问答页面模型}：
界面遵循通用的左右视频学习布局，左侧上方镶嵌经过全屏定制化的 HTML5 \texttt{<video>} 组件，允许接收外部的精确 Seek 和自动锚定启播指令；右侧固定宽度（约 30\%）挂载独立的 AI Chat 流式对话流（仿 ChatGPT 界面设计风格）。
\textbf{体验交互说明}：当视频教学概念晦涩时，在此页面右侧的对话框中无缝查询；服务器返回流中解析出的形如“\texttt{[来源: 05:22]}”小标签会被正则编译为带有特定 CSS 样式的微秒链接组件。点击时，触发 Vue3 的全局事件总线机制驱动播放器 DOM，用户视角将在当前页“秒滑”至提及该原理的字幕片段位置，达到视觉与认知完美同步的教育产品质感。
