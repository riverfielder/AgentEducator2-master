\chapter{系统实现}

\section{核心算法与引擎实现}

本系统的核心竞争力在于突破了传统在线教育平台仅能提供“文本 CRUD（增删改查）”的局限，深度集成了抽象语法树（AST）静态分析、检索增强生成（RAG）以及大语言模型（LLM）的调度。本节将详细阐述这些核心链路的代码级实现与数学原理。

\subsection{基于 AST 的代码诊断与启发式评估实现}

为实现真正的“苏格拉底式”启发辅导，系统在前端代码提交至后端沙箱运行之前，前置了一个基于 Python 内置 \texttt{ast} 模块的静态白盒引擎。

在 \texttt{ASTParser} 类中，通过重写 \texttt{NodeVisitor} 的递归遍历逻辑，我们可以不执行代码即可探测诸如“未使用变量”、“嵌套过深的循环”等结构复杂性问题与语法特征。

\begin{lstlisting}[language=Python, caption=AST 静态分析提取圈复杂度片段]
import ast

class CodeAnalyzer(ast.NodeVisitor):
    def __init__(self):
        self.complexity = 1
        self.issues = []

    def visit_For(self, node):
        self.complexity += 1
        if len(node.body) > 0 and isinstance(node.body[0], ast.For):
            self.issues.append("存在多层嵌套循环，考虑优化时间复杂度 O(n^2)")
        self.generic_visit(node)
        
    def visit_If(self, node):
        self.complexity += 1
        self.generic_visit(node)
\end{lstlisting}

上述代码提取的 \texttt{issues} 会作为背景知识（Context）前置给大语言模型结构，确保大模型的视界不仅局限于代码的字面输出，更能深刻理解代码的抽象层级和架构拓扑。

\subsection{基于 FAISS 与 RRF 重排的混合 RAG 问答实现}

针对视频教程的衍生式知识问答，系统构建了带有 FAISS 高维稠密向量索引与 BM25 稀疏词频索引的双路召回系统。为解决单一向量检索在专有名词（如“死锁”、“并发”、“Vue生命周期”）上字面映射精度不足的问题，本课题采用了倒数秩融合算法（Reciprocal Rank Fusion, RRF）对双路召回的结果进行重排（Rerank）机制设计。

其核心计算公式为：
\begin{equation}
RRF\_Score(d) = \sum_{r \in R} \frac{1}{k + r(d)}
\end{equation}
其中，$r(d)$ 表示知识切片 $d$ 在单路召回（无论是 FAISS 还是 BM25）中的排名，常数 $k$ 为抗干扰平滑项（本系统工程实践中取经验值 60）。

具体实现中，我们将各个引擎召回的视频字幕切片进行整合：
\begin{lstlisting}[language=Python, caption=双路混合 RRF 重排融合算法核心实现]
def compute_rrf(faiss_results, bm25_results, k=60):
    rrf_scores = defaultdict(float)
    
    # 结合 FAISS 密集检索排位积分
    for rank, doc in enumerate(faiss_results):
        rrf_scores[doc.id] += 1.0 / (k + rank + 1)
        
    # 结合 BM25 稀疏检索排位积分
    for rank, doc in enumerate(bm25_results):
        rrf_scores[doc.id] += 1.0 / (k + rank + 1)
        
    # 依据系统融合得分降序排列并抽取 Top-K
    return sorted(rrf_scores.items(), key=lambda x: -x[1])
\end{lstlisting}
将重排得分最高的前 $Top-K$ 个字幕片段文本及其对应的视频秒级时间戳注入到 LangChain 的 Prompt Template 中。此举极大地抑制了 LLM 的事实性幻觉（Hallucination），同时通过时间戳实现了前端交互中的视频自动回跃。


\subsection{基于微观 AST 掌握度与宏观知识图谱联动的大模型个性化引擎}

虽然 AST 和 RAG 解决了微观层面的“题目辅导”和“视频解惑”，但系统要扣紧“基于大模型辅助个性化学习系统”的主题，必须在教学路径与专项训练上实现双端个性化。通过对后端代码真实实现的剖析，本系统摒弃了传统的协同过滤等可能面临“冷启动”问题的查表算法，创新性地提出了【微观掌握度实时量化】结合【宏观知识图谱推演】的计算链路。

在微观训练路由（/generate-personalized）中，当学生的底层知识点（如“Python类的继承”）被判定为薄弱时，系统动态调度大模型针对性出题（涵盖单选、多选与主观代码题），以强迫学生进行补短板复练，主观题提交后再次辅以底层 AST 词法检测进行多维度判分；在宏观学习路径演进流中，系统查表获取用户当前的最高掌握度知识节点（KnowledgePointMastery），随后利用知识点间的上下游依赖（prerequisite、extends 等关联关系）计算出其紧前与紧后的前置或衍生知识域，最终交由统一的大语言模型决策中枢（UnifiedLLMService）作为 Prompt 动态预判其最合理的进阶学习曲线。其核心决策拼接思路的抽象部分实现如下：

\begin{lstlisting}[language=Python, caption=结合图谱游走与大语言模型的定制化推荐提示词推理拼接引擎]
def _build_ai_recommendation_prompt(self, knowledge_context, mastery_overview, limit):
    prompt = f"""
    你是一个智能学习路径推荐专家。请基于以下用户学习情况和知识图谱信息...
    ## 用户学习概览
    - 总学习知识点: {mastery_overview.get('total_keywords', 0)}
    - 平均掌握度: {mastery_overview.get('average_mastery', 0):.1%}
    ## 用户掌握较好的知识点（源知识点）
    """
    for keyword in knowledge_context['mastered_keywords']:
        prompt += f"- {keyword['name']} (掌握度: {keyword['mastery_level']:.1%})\n"

    prompt += "## 与以上知识点相关联的前置与衍生知识点（等待被推荐的知识点）\n"
    for option in knowledge_context['available_next_steps'][:20]:
         # 基于知识图谱的（extends/prerequisite）等关系注入
         prompt += f"- {option['name']} (分类: {option['category']})\n"
         
    return prompt
\end{lstlisting}
由上述代码可知，算法在保留纯图推理的严谨性的同时，利用大语言模型的自然语言理解能力替代了传统硬编码的推荐算分逻辑，能够给出含有“推荐语”的精准柔性引导，具有较强的教学应用价值。


\section{系统鲁棒性保证与异常降级策略 (Fallback)}

针对系统实际部署中强调的系统稳定性与不可控因素屏蔽问题，本平台着重设计了异常熔断双层防御隔离机制。

（1）\textbf{沙箱死锁与进程内存越界防护}：
学生的脏代码在送入子进程沙箱执行时，使用了 OS 原生的进程控制边界资源 \texttt{resource} 模块进行严格包围。硬编码限制其最大执行时间阈值为 3 秒、CPU调度切片与内存使用峰值定为 128MB。当捕获 \texttt{TimeoutError} 后，主控将终结僵尸进程，将其转化为错误报告发送给 LLM 诊断。

\begin{lstlisting}[language=Python, caption=沙箱进程核心限流与超时保护片段]
import resource
import signal

def time_exceeded(signum, frame):
    raise TimeoutError("执行超时: 疑似遭遇死循环或大量I/O阻塞。")

def set_sandbox_limits():
    # 严格限制 CPU 运算时间上限 3 秒
    resource.setrlimit(resource.RLIMIT_CPU, (3, 3))
    # 限制虚拟内存映射 128MB 防治 OOM 直接崩溃
    mb = 128 * 1024 * 1024
    resource.setrlimit(resource.RLIMIT_AS, (mb, mb))
    # 挂载 SIGVTALRM 时钟信号钩子触发异常
    signal.signal(signal.SIGVTALRM, time_exceeded)
\end{lstlisting}

（2）\textbf{云端大模型通信熔断与软降级策略}：
作为依赖第三方 LLM 推理的 AI 辅助应用，其网络通信具备较高的不确定性。当云端 API 请求超限（> 10 秒无响应）或配额告竭时触发断路器。系统不再抛弃请求，而是进入“规则评估降级反馈模式”，此时仅输出 AST 单向扫描报告与黑盒执行 Traceback 堆栈，剥离启发文本生成组件，确保系统至少处于基础评测系统的全天候可用状态。

\section{长连接流式通讯与应用层服务实现}

在上述底层功能库之上，基于 Flask 和 Vue3 构造了微服务通信链路。为了提升“打字机式答复”体验并避免 HTTP 短连接池堵塞，针对问答业务开启 Server-Sent Events (SSE)。

\begin{lstlisting}[language=Python, caption=Flask 中的 SSE 返回报文装配]
from flask import Response, stream_with_context

@app.route('/api/qa/ask-stream', methods=['POST'])
@login_required
def ask_stream():
    # ...截取参数执行 RAG 引擎...
    def generate_events():
        for chunk in llm_qa_chain.stream({"context": ctx, "query": q}):
            # 将每个大模型帧拆解并通过 HTTP 长连接下推
            yield f"data: {json.dumps({'token': chunk.content})}\n\n"
    return Response(stream_with_context(generate_events()), mimetype='text/event-stream')
\end{lstlisting}
该特化接口不仅解决了浏览器拉取白屏干等问题，同时在客户端基于正则过滤器实现了对如 `[来源: 05:20]` 帧模式的高亮渲染匹配。通过组合式 API 中的 `watch` 及全局 Pinia 事件，前端将其转译成了触发 `<video>.currentTime = 320` 的动作闭环跳转指令。
